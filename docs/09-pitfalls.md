# 09 · 踩过的坑

每条都写了：现象 → 原因 → 规矩。

## 上下文与文档

**1. CLAUDE.md 太大，后半部分读不到**
- 现象：59 KB 的 CLAUDE.md，最关键的“已知 bug 模式”在后半段，新会话根本不知道。
- 原因：常驻文件有加载上限；越长遵循度越低。
- 规矩：根 CLAUDE.md ≤ 200 行；区域知识放 `.claude/rules/` + `paths:`；流程放 skill。

**2. 把文档放进会被打包的目录**
- 现象：在 Xcode 同步源码目录里放了 7 个 `CLAUDE.md`，构建失败，报 "Multiple commands produce …/CLAUDE.md"。
- 原因：同步目录会把所有非代码文件当资源拷进 app 包。Android `assets/`、Web `public/`、某些 bundler 的静态目录也一样。
- 规矩：这类目录里不放任何文档，改用根部 rules 的 `paths:`。

**3. 文档里写会过期的数字**
- 现象：CLAUDE.md 写着“约 530 行”，实际 834；同一功能一处写“默认开启”，另一处写“默认关闭”。
- 规矩：不写行数和历史；同一事实只写一处；`/doctor prompt-audit` 查冲突。

**4. 说“有测试”但测试 target 是空的**
- 现象：`xcodebuild test` 必失败，却没人写下来；新会话每次都去试。
- 规矩：L0 就把“怎么测、哪些不能测”写准。

## 验证

**5. 演示数据掩盖 bug**
- 现象：图片 URL 为空的演示数据让一个“铺满图片撑大布局”的 bug 完全不出现，真机部署了三次“修好了但没修好”。
- 规矩：演示 / 测试数据要像真的：真实图片、长文本、空状态、错误状态。

**6. 用错构建配置做测量**
- 现象：用 Release 构建测性能，可“跳过登录”的调试开关在 Release 里被编译掉，app 一直停在登录页，第一轮数据全部作废。
- 规矩：测量前确认开关在该配置下存在；结论里写明构建配置。

**7. “编译通过 = 完成”**
- 规矩：门禁 + 行为验证 + 结论格式。截图要亲眼看，不能只看 agent 的描述。

**8. 模拟器 / mock 推断真机行为**
- 现象：语音识别在模拟器上没有模型，转写根本不跑。
- 规矩：列出真机才能验证的项，写进 Not covered，交给人。

## 自动化与权限

**9. 后台 agent 没有审批权限**
- 现象：后台委派的 agent，所有 shell 命令、桌面目录写入都被自动拒绝，等于什么都没做。
- 规矩：需要跑命令或写到项目外的工作，要么前台运行，要么提前在 `permissions.allow` 里放行。

**10. Stop hook 死循环**
- 规矩：必须检查 `stop_hook_active`；只提醒一次；允许 agent 用一句话说明为什么不需要。

**11. hook 输出夹杂非 JSON**
- 规矩：stdout 只输出 JSON；出错静默 `exit 0`；用管道喂样例 JSON 测试。

**12. lint 规则一上线就满屏红**
- 规矩：先修存量，或给合理的地方加 `lint:allow` 写明理由，再启用规则。

**13. 路径通配写错，漏掉顶层文件**
- 现象：git pathspec `'src/**/*.swift'`（非 glob 模式）匹配不到 `src/App.swift`，因为 `**/` 至少要求有一层目录。改顶层文件后，收尾提醒不会触发。
- 规矩：在 git 默认 pathspec 里，`*` 可以跨目录，用 `'src/*.swift'` 即可；或者显式加 `:(glob)`。写完拿顶层文件测一遍。

## 协作

**14. 重复实现的逻辑靠“记得同步”**
- 现象：播放和下载各有一份音源回退链，注释写着“保持同步”。
- 规矩：抽成唯一实现，再用 lint 规则禁止在别处手写（架构 > lint > 文字）。

**15. 在没敲定的需求上开工**
- 规矩：需求还需要探索或确认时，先复述，必要时出方案，确认后再实现。

**16. 一上来就把所有东西配满**
- 规矩：按 L0→L5，碰到触发条件再升。没用到的 skill / 插件会持续占用上下文。

**17. 用户问的范围和后续消息不一致**
- 现象：用户先选了“只改配置层”，紧接着又说“去重也可以做”。
- 规矩：以最新消息为准，但把有风险的部分（例如改了播放路径）单独提交，并明确告诉对方需要真机回归。
